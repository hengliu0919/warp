Kiro keeps every multiline prompt row visible

Warp no longer reserves its coding-agent footer rows for Kiro sessions. Kiro remains detected and branded, while its self-rendered V3 prompt owns the terminal viewport.

At a glance

Before
Detecting Kiro enabled Warp's footer rich content. On the reported macOS build, repeated Shift+Enter input descended behind that footer.
After
Kiro opts out of the outer footer, so its growing prompt can scroll and keep the cursor line visible.
Unchanged
Kiro command detection, branding, telemetry, terminal key decoding, and footer support for other compatible CLI agents.

Review limit: the original macOS failure is directly visible in the reporter's recording, but the after-fix client was exercised on Linux/X11. A local macOS after-fix run was unavailable.

Why this is needed

Warp first added Kiro as a first-class coding agent in October 2026. That integration caused Kiro to inherit the coding-agent footer even though the integration PR recorded that authenticated multiline delivery and macOS behavior were not exercised.

Kiro V3 renders a live prompt that grows toward the bottom edge. Its own decoder already accepts Ctrl+J, CSI-u Shift+Enter, xterm modifyOtherKeys, and ESC-prefixed Enter. The failure starts when Warp adds a second owner for those bottom rows.

History: Warp Kiro integration PR #16243 · Kiro CSI-u handling PR #3616.

Decisions

Model footer compatibility as an agent capability

The fix changes CLIAgent::supports_cli_agent_footer() for Kiro. It does not inspect the host terminal, rewrite input bytes, or special-case Warp versions. The accepted cost is that Kiro sessions temporarily lose Warp's footer toolbar.

Alternatives actually checked

A Kiro input-height or key-decoding fix was rejected after the exact nightly and current Kiro tests handled every relevant sequence in Linux PTYs and in real Warp. A broad footer disable was rejected because other CLI agents use bounded composers and existing footer behavior remains valid for them.

Key areas and invariants

Narrow compatibility boundary

The exception is attached to the Kiro agent variant, not to macOS, Warp Terminal detection, or a global rendering switch. Other terminals are unaffected because this code runs inside Warp; other Warp CLI-agent sessions retain their existing footer.

Detection remains intact

Kiro still matches its command prefixes and remains available for brand color, session tracking, and telemetry. Only footer insertion is suppressed.

Implementation walkthrough

Before

  1. Warp recognizes a long-running Kiro command.
  2. supports_cli_agent_footer() returns true.
  3. Warp appends footer rich content below the active block.
  4. Kiro's live prompt and Warp's footer compete for bottom rows.

After

  1. Warp recognizes the same Kiro command.
  2. supports_cli_agent_footer() returns false.
  3. The existing render guard exits before inserting rich content.
  4. Kiro owns the full viewport and scrolls its prompt normally.
pub(crate) fn supports_cli_agent_footer(&self) -> bool {
    !matches!(self, CLIAgent::Kiro | CLIAgent::WarpTui)
}

Source: footer capability · regression test.
